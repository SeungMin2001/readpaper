# 용어 번역 지연 검증 기록

2026-10-15 기준, **새 용어를 Gemma 4 12B로 1초 안에 번역하는 목표는 아직 실측하지 못했다.**
Codex의 Linux 작업 환경에서 사용자의 Mac mini 모델 서버로 연결되는 경로가 없다.
작업 환경의 `127.0.0.1:8001`은 연결 거절, `host.docker.internal`은 접근 실패였다.
모델을 교체하거나 사전 번역을 추가하지 않았다.

## 변경한 경로

1. 서버가 원문에서 클릭 위치와 일반적인 AI 복합 용어의 범위를 결정한다.
2. 모델 입력은 고정 지시문, 저장된 한 문장 논문 요약, 선택한 용어다.
3. 모델 출력은 한국어 뜻만 받는다. 영어 원문·JSON 키·범위를 생성하지 않는다.
4. `enable_thinking=false`를 명시하고 HTTP 연결을 재사용한다.
5. 동일 논문·요약·모델·서버·용어의 뜻은 SQLite에서 재사용한다. 동시 요청도 같은 입력이면 추론 한 번을 공유한다.
6. 재사용한 뜻의 단어 ID는 현재 위치에 다시 연결한다. 다른 페이지의 위치를 복사하지 않는다.
7. 잘리거나 비정상적인 응답은 저장하지 않는다. 실패 후 재시도할 수 있다.

등록된 영어 복합 용어 목록에는 번역값이 없다. 등록되지 않은 복합 용어는 클릭한 단어로만 처리한다.
한 문장 요약만으로 구별할 수 없는 다의어의 정확도는 별도 평가가 필요하다.

지시문과 요약을 요청 앞부분에 고정해 prefix caching이 가능한 구조로 만들었다.
[vLLM-Metal 지원 모델 문서](https://github.com/vllm-project/vllm-metal/blob/main/docs/supported_models.md)는
Gemma 4의 prefix caching 지원을 명시하지만, 사용자의 설치 버전과 실행 옵션에서 실제 적중하는지는 확인하지 못했다.
`cached_prompt_tokens`가 없으면 미보고 값으로 유지하며, 적중한 것으로 가정하지 않는다.

## 실행한 검증

| 검증 | 결과 | 범위 |
| --- | --- | --- |
| Python 자동 테스트 | 39개 통과 | 업로드·요약·RAG 회귀, 용어 매칭, 캐시 격리, 동시 요청, 오류 재시도, 응답 검증 |
| Docker 내부 자동 테스트 | 같은 39개 통과 | 실제 배포 이미지에 설치된 라이브러리로 실행 |
| 프론트엔드 | TypeScript 검사·Vite 빌드 통과 | 브라우저 클릭 후 응답 시간을 표시하는 코드 포함 |
| Docker 이미지 | 빌드 성공 | 모델 가중치를 포함하지 않는 웹/API 이미지 |
| 컨테이너 HTTP | health·개발 사용자·프론트엔드 200 | 실행 중인 웹 서버에 실제 HTTP 요청 |
| 실제 Gemma 요청 | 연결 실패, 종료 코드 2 | 샘플 0개, `goal_met=false` |

자동 테스트의 모델과 문헌 API는 모의 응답을 사용한다. 이 테스트 통과가 실제 번역 품질이나 GPU 속도를 입증하지 않는다.

## 캐시 처리만 측정한 결과

Linux Docker 컨테이너 안의 실제 HTTP API에 요청했다. 10페이지·5,000단어의 합성 문서에
테스트용 뜻을 미리 저장한 뒤, 서로 다른 50개 위치에서 같은 용어를 조회했다.
모델은 호출하지 않았으며 브라우저 렌더링 시간도 포함하지 않았다.

| 요청 수 | 중앙값 | p95 | 최대 |
| --- | --- | --- | --- |
| 50 | 17.60 ms | 24.37 ms | 141.40 ms |

이 수치는 캐시를 재사용하는 경로의 검증이다. 새 용어 번역의 1초 목표 달성 결과로 사용할 수 없다.

## 실제 모델 측정 재개

맥 미니에 연결 가능한 환경에서 아래 명령을 실행한다. 첫 명령은 이전 JSON 요청과 뜻 전용 요청을 비교한다.
명령 자체는 앱의 번역 결과 캐시를 사용하지 않으며 모델 서버의 prefix caching은 사용할 수 있다.

```bash
docker compose exec web python /app/backend/scripts/benchmark_gloss.py --compare --json-out /data/gloss-model-benchmark.json
```

다음 명령은 이미 업로드된 논문의 서로 다른 용어를 웹 API에 요청한다. 첫 생성과 결과 캐시 적중을 따로 집계한다.
운영 인증이 켜져 있으면 컨테이너의 기존 사용자 설정으로 로그인한다.

```bash
docker compose exec web python /app/backend/scripts/benchmark_gloss.py --latest-paper --api-url http://127.0.0.1:8000 --repeats 2 --json-out /data/gloss-api-benchmark.json
```

- 기본 제한은 완성된 응답까지 1,000ms 미만이다. 새 뜻 중 하나라도 넘으면 종료 코드 1이다.
- 서버 연결 실패는 종료 코드 2다. 모든 요청이 캐시에 적중했어도 새 뜻 목표 달성으로 처리하지 않는다.
- 중앙값·p95·최대값·오류·실제 번역문을 함께 저장한다. 속도와 번역 품질을 함께 확인해야 한다.
- `first_token_ms`는 첫 텍스트까지의 대기, `after_first_token_ms`는 이후 완료까지다. 순수 GPU prefill/decode 시간이 아니다.
- HTTP API 측정은 브라우저 렌더링을 제외한다. 화면의 시간은 브라우저에서 클릭 후 API 응답까지 측정한다.
- 실제 측정 전에 Mac과 클라우드 사이의 사설 연결 또는 Mac에서 실행되는 Codex 작업 환경이 필요하다.
