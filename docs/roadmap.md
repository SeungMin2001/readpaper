# Readpaper 진행 단계

제품 범위는 [product-brief.md](product-brief.md)를 따른다. LLM은 Mac mini에서 서빙하고, 웹/API와 저장소는 클라우드에 둔다. PDF 화면 검증과 클라우드 계정 준비는 모델 연결 없이 시작할 수 있다.

## 1. 검증 자료와 성공 기준 준비

- 글자를 선택할 수 있는 실제 AI 논문 PDF 3편 이상을 고른다. 2단 편집, 표, 수식, figure, 여러 단어로 된 전문 용어가 들어간 논문을 포함한다.
- 단어·전문 용어의 문맥별 한국어 뜻과 근거 있는 질문·답변을 비교할 작은 평가 목록을 만든다.
- 측정 항목을 정한다: PDF 원본 표시, 클릭 위치 정확도, 용어 범위와 의미 정확도, 반복 용어 일관성, 클릭 응답 시간, 논문 한 편의 준비 시간, 질문 답변의 출처 정확성.

완료 기준: 대표 PDF와 평가 사례가 있어 도구·모델을 같은 조건에서 비교할 수 있다.

## 2. PDF 읽기 화면 검증

- PDF.js로 PDF의 글과 figure를 원본 위치에 표시한다.
- 단어를 눌러 문맥상 짧은 한국어 뜻을 확인하고 다시 원문으로 되돌리는 화면을 만든다.
- 여러 단어로 된 전문 용어는 전체 표현을 하나의 뜻으로 보여주고, 각 단어를 눌러도 같은 용어로 인식되는지 확인한다.
- 2단 편집, 줄바꿈, 수식 주변, 텍스트 선택 불가 영역을 점검한다.

완료 기준: 대표 PDF에서 그림과 글 배치를 유지하고, 클릭한 원문과 표시할 번역을 안정적으로 연결할 수 있다. 이 단계의 LLM 사용은 없다.

## 3. Mac mini 모델 서빙과 클라우드 연결

- Mac mini에서 vLLM-Metal로 Gemma 4 12B를 서빙한다. 실제 평가 문장으로 뜻의 품질·응답 시간·메모리를 확인하고, 공개 서비스에서는 동시 요청 처리와 비용을 측정한다.
- AWS를 클라우드 우선 후보로 두고 계정 보안, 비용 알림, 웹/API 서버 비용을 확인한다. Azure가 더 적합하면 바꿀 수 있다.
- Mac mini와 클라우드 사이에 인증된 전용 연결을 만들고, 클라우드 API에서 모델 상태와 실제 추론을 검증한다. 모델 포트를 공개 인터넷에 열지 않는다.

완료 기준: 클라우드의 API가 Mac mini 모델에 안전하게 요청하고, 같은 입력에 대해 재현 가능한 평가 결과를 얻는다.

## 4. 논문 전체 선처리와 근거 있는 질문·답변

- PDF에서 문장, 절, 전문 용어, figure 설명과 화면 위치를 추출한다. PDF.js 결과와 Docling 또는 GROBID 같은 분석 도구를 실제 논문으로 비교한다.
- 업로드 시 논문 본문을 한 문장으로 요약해 저장한다. 요약·업로드 원문 색인 완료 후 읽기 화면을 열고 외부 문헌은 계속 수집·색인한다. 용어는 누를 때 번역하며 준비 중 원문 먼저 열기도 제공한다. 문장 전체 번역은 생성하지 않는다.
- 사용자가 단어를 누르면 서버가 원문에서 단어·일반적인 AI 복합 용어의 범위를 정하고, 저장한 한 문장 요약과 선택 용어만 모델에 보내 짧은 한국어 뜻을 만든다. 동일 논문·요약·모델·용어의 결과는 다른 위치에서도 재사용한다.
- 업로드 논문이 인용한 논문의 전체 목록과 서지 정보를 가져오고, 각 논문의 이용 가능한 공개 전문 확보를 시도한다. 관련·후속 인용 논문은 최신성·주제 관련도로 범위를 정한다. 전문을 구조 기반으로 청킹해 저장하고, 벡터·키워드 검색과 리랭킹으로 답변 근거를 찾는다. 전문을 얻지 못한 자료는 초록만 사용한다고 표시한다. 구현 순서와 평가 기준은 [RAG 확장 설계](rag-design.md)를 따른다.
- PDF 원본과 분석 결과의 수명 주기를 구현한다. 분석 결과는 마지막 사용 후 24시간에 만료하고, 같은 PDF를 다시 선택하면 그 안에 재사용한다.

완료 기준: PDF를 넣으면 핵심 요약을 준비한 뒤 원문을 열고, 누른 단어는 요약을 반영해 뜻을 만든다. 같은 위치를 다시 누르면 저장된 뜻을 즉시 보여준다. 새 질문에는 Mac mini가 켜져 있을 때 근거와 함께 답한다.

## 5. 개인용 웹 서비스 완성

- 본인만 사용할 로그인, PDF 업로드, 진행 상태, 읽기 화면, 단어 자동 기록·직접 추가·삭제, 단어장을 연결한다.
- 단어장만 지속 저장한다. PDF·본문·벡터는 마지막 사용 후 24시간까지 임시 보관하고 읽던 위치는 저장하지 않는다.
- 오류가 난 PDF, 분석 실패, 번역이 누락된 단어에 대한 사용자 안내를 만든다.

완료 기준: 로그인부터 PDF 읽기와 단어 복습까지 한 번의 흐름으로 동작한다.

## 6. 배포와 포트폴리오 검증

- Docker로 웹·API·분석 작업까지 재현하고, 자동 배포·로그·비용 추적을 추가한다.
- 웹/API와 모델 서버를 분리하고 Mac mini 연결이 끊겼을 때의 오류 안내와 복구를 검증한다.
- 실제 동시 분석·질문 요청이 생길 때 작업 대기열과 확장 방식을 검증한다. Kubernetes는 기본 서비스가 동작하고 운영 지표가 나온 다음 적용 여부를 판단한다.
- 용어 뜻 품질, PDF 선택 정확도, 원문 준비 시간, 클릭 응답 시간, Mac mini 모델 처리량과 클라우드 비용을 측정해 설계 이유와 함께 기록한다.

완료 기준: 새 환경에서 재현 가능한 배포와 실제 논문을 이용한 검증 결과가 있다.

## 이번 구현 상태

PDF 선택·그림 첨부·채팅 출처·웹 전문 수집·LangChain 청킹·Mac mini E5 임베딩 API·Qdrant 하이브리드 검색 연결을 구현했다. 실제 검증과 남은 제한은 [채팅·RAG 검증](workspace-rag.md)에 기록한다. Mac mini 실측, 별도 리랭커와 작업 큐는 후속 단계다.

## 후속 평가

1. 대표 AI 논문 PDF와 평가할 단어·전문 용어를 고른다.
2. PDF 읽기 화면의 선택·번역 표시가 가능한지 실험한다.
3. Mac mini에서 vLLM-Metal 모델 서버를 실행하고, 동시에 AWS 계정의 보안·비용 알림과 웹/API 서버 구성을 확인한다.
